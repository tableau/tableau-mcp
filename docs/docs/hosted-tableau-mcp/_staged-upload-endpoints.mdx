Tableau MCP hands files to and from your agent through short-lived presigned S3 URLs. These
tools use them:

- [`scaffold-data-app`](/tools/data-apps/scaffold-data-app.md) returns an `s3URL` the agent
  **downloads** the starter template from.
- [`request-workbook-upload`](/tools/workbooks/request-workbook-upload.md) returns an `uploadUrl`
  the agent **uploads** the workbook to before `publish-workbook`.

The agent's own environment makes these requests, not the Tableau MCP server. If that environment
restricts outbound network access (a sandbox, a code-execution container, or an organization
allowlist), you must allow the S3 host for your Tableau pod. This is a **client configuration
step**: nothing on the Tableau side can change it.

If the host is blocked, the download or upload fails with a network or `403` error. Allow the host
and retry. Don't work around the failure with a custom script against the Tableau REST API, because
that bypasses the checks and consent step in the MCP publish flow.

Find your pod in your site URL (for `https://10ax.online.tableau.com`, the pod is `10ax`), then
allow its host.

### Using your own blob storage

If you run your own Tableau MCP server and set
[`MCP_S3_BUCKET`](/configuration/mcp-config/env-vars.md#mcp_s3_bucket), the pod hosts above don't
apply. Presigned URLs point at your bucket instead, so allow your bucket's host:

```text
<your-bucket>.s3.<region>.amazonaws.com
```

Use the bucket name from `MCP_S3_BUCKET` and the region from `AWS_DEFAULT_REGION`. If you're not
sure of the exact host, call `request-workbook-upload` once and read the host from the returned
`uploadUrl`. To cover several buckets in one region, allow `*.s3.<region>.amazonaws.com`.
